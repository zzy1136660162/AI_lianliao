## 1. 文档目标

本文定义“链上辽宁·产业云城”企业工作台从企业、产品、在建项目查询工具扩展为企业业务协同桌面平台的产品与技术方案。设计覆盖：

- 企业桌面工具管理、消息提醒、运行诊断和版本更新整合；
- 企业码与企业资料运营；
- 供需发布、匹配和对接；
- 在建项目潜在商机、收藏、解锁和跟进；
- 客服人员使用的接待工作台；
- 企业会员、积分、收费、权益和数据发布。

本文只冻结产品边界、信息架构、核心状态、数据流、安全边界和验收原则。具体源文件、实施步骤和测试命令在书面设计通过后由独立实施计划定义。

| 决策项       | 结论                                                                  |
| ------------ | --------------------------------------------------------------------- |

| 开发方式     | Electron 主进程、preload 和 renderer 继续使用严格 TypeScript          |

| 后端边界     | 仅在桌面闭环确有需要时修改 `cloud-service`                            |

| 分支         | 按用户要求直接在 `master` 开发，每个阶段保持独立提交                  |

## 4. 总体产品结构

企业工作台左侧导航按业务分组，不把所有入口平铺成一条长菜单。

```text
链上辽宁·产业云城
├─ 工作台
├─ 数据资源
│  ├─ 企业库
│  ├─ 产品库
│  └─ 在建项目
├─ 业务协同
│  ├─ 供需对接
│  ├─ 商机跟进
│  └─ 我的收藏
├─ 客户运营
│  ├─ 客服工作台
│  ├─ 会员与积分
│  └─ 企业数据发布
├─ 消息与工具
│  ├─ 消息中心
│  └─ 桌面工具
└─ 固定底部
   ├─ 当前企业和用户
   ├─ 进入链辽AI
   ├─ 设置
   └─ 退出登录
```

“我的企业码”作为当前企业身份卡和工作台快捷入口存在，不再额外占用一级导航。

## 5. 企业视觉系统

### 5.1 作用域

企业视觉变量挂在企业壳根节点，只对企业登录页和 `/enterprise/**` 生效。链辽AI继续使用原有主题与字体设置。企业空间固定使用明亮主题，不跟随链辽AI的深色主题。

### 5.2 字体

企业工作台新增 UI 字体变量，首选：

```text
"Microsoft YaHei", "微软雅黑", "Segoe UI", Arial, sans-serif
```

适用规则：

- 正文和数据说明：400；
- 菜单、按钮、表单标签和强调正文：500；
- 页面标题和卡片主数值：600；
- 代码、路径、版本号和技术诊断值继续使用等宽字体；
- 移除企业页面当前强制使用的中文衬线标题和无业务必要的等宽标签。

### 5.3 公共变量

企业公共样式至少定义以下语义变量：

```text
--enterprise-font-ui
--enterprise-page-bg
--enterprise-surface
--enterprise-surface-soft
--enterprise-border
--enterprise-primary
--enterprise-text-primary
--enterprise-text-secondary
--enterprise-radius-card
--enterprise-radius-control
--enterprise-shadow-card
--enterprise-shadow-hover
--enterprise-content-gap
```

卡片圆角统一为 15px；按钮、输入框和标签采用 8–10px 圆角。组件只引用语义变量，不各自硬编码颜色、圆角和阴影。

### 5.4 布局和滚动

- Electron 页面根节点固定在可视高度内，业务内容不直接拉长窗口；
- 左侧菜单固定宽度并可独立滚动；
- 中间业务区是主要滚动容器；
- 客服会话列表、消息区和右侧资料区分别独立滚动；
- 弹窗、抽屉和详情面板限制最大高度；
- 表格放在白色卡片中，但表格行保持平整和高数据密度；
- 卡片悬停只轻微上浮并增强阴影，不使用持续或夸张动画。

## 6. 工作台首页

首页按“指标、趋势、待办、商机、快捷动作”组织：

1. 顶部标题区：页面说明、刷新、消息和快速发布；
2. 指标区：新增供需、待跟进商机、客服未读、可用积分；
3. 中部主区：30 天供需趋势和待办/推荐/公告；
4. 底部：最新潜在商机、快捷操作和运行状态。

首页指标必须来自真实后端聚合。相应业务未上线或没有数据时显示明确空状态，不使用固定演示数字。

## 7. 企业码中心

当前企业身份卡提供“我的企业码”入口，详情展示：

- 企业名称、企业码二维码和可复制分享链接；
- 企业认证状态、会员等级和有效期；
- 企业资料完整度；
- 已发布产品、供给和需求数量；
- 客服绑定状态和未读消息；
- 企业码预览。

企业资料不能从桌面直接覆盖线上正式数据。修改进入草稿，提交后经过审核，审核通过才成为线上数据。

## 8. 供需对接

### 8.1 页面

供需模块包含四个页签：

- 供给大厅；
- 需求大厅；
- 智能推荐；
- 我的发布与对接记录。

列表支持关键词、行业、地区、供需类型、状态和发布时间筛选。详情展示发布企业、内容、有效期、联系方式权限、相关产品和匹配依据。

### 8.2 操作

- 收藏；
- 发起询价或对接；
- 加入商机跟进；
- 查看发布企业；
- 发布供给或需求；
- 下架、编辑草稿和重新发布本企业数据。

### 8.3 匹配

第一阶段使用可解释的行业、产品分类、地区和关键词规则。只有后端返回匹配分数与依据时才展示“匹配度”，renderer 不自行生成 AI 匹配率。

## 9. 在建项目潜在商机

保留现有项目看板、列表和详情，增加：

- 收藏项目；
- 查看匹配产品或原材料；
- 加入商机跟进；
- 会员权益校验；
- 解锁联系方式；
- 跟进记录时间线。

商机跟进状态固定为：

```text
TODO（待跟进） → DOING（跟进中） → DONE（已完成）
```

收藏状态和跟进状态相互独立。状态更新只有在服务端成功后才落到本地界面；失败必须恢复原状态并给出可重试反馈。

## 10. 我的收藏

收藏页统一承载企业、产品、项目、供给和需求，支持类型筛选、分页、跳转和取消收藏。

已知旧数据映射：

| 目标     | `J_CY_INTEREST.TYPE` |
| -------- | -------------------- |
| 企业     | `1`                  |
| 产品     | `2`                  |
| 在建项目 | `6`                  |

供给和需求的数字类型必须在实施前核对现有数据库和旧入口，不能在客户端猜测。renderer 使用稳定业务枚举，数字类型由后端集中映射。

收藏写入需支持首次保存、重复保存幂等、取消、取消后恢复和并发保护。对象下线时保留收藏记录和下线标记。

## 11. 会员、积分和收费

### 11.1 会员账户

会员中心展示：

- 当前会员等级、有效期和认证状态；
- 可用、冻结和即将过期积分；
- 产品、供给和需求的剩余发布额度；
- 项目联系方式剩余解锁次数；
- 客服席位数量；
- 套餐权益和订单记录。

会员等级、价格、额度和权益全部由后端配置返回，桌面端不硬编码套餐规则。

### 11.2 积分账本

每条积分记录包含业务来源、增减数量、前后余额、关联对象、时间、状态和过期时间。积分扣减使用数据库事务和幂等键；项目解锁的重复点击或网络重试最多扣除一次。

### 11.3 桌面收费

Electron 使用二维码支付：

```text
创建订单 → 生成付款二维码 → 桌面轮询状态 → 支付平台回调 → 开通权益 → 刷新账户
```

订单状态至少包含创建、待支付、已支付、已关闭和已退款。只有可信支付回调可以把订单改为已支付，renderer 无权修改支付结果。

### 11.4 统一权益

后端使用稳定权益代码表达能力，例如项目联系方式解锁、产品发布、供需发布、客服席位、高级推荐和导出。业务页面只查询和消费权益，不按会员等级在多个页面重复写判断。

## 12. 企业数据发布

发布范围包括企业资料、产品、供给和需求，状态机为：

```text
DRAFT（草稿） → PENDING（待审核） → PUBLISHED（已发布）
                                     ↘ REJECTED（已驳回） → 修改后重新提交
PUBLISHED（已发布） → OFFLINE（已下架）
```

提交前由后端检查当前企业归属、会员权益、剩余额度、必填字段、资源有效性、重复请求和内容规则。发布、审核、驳回和下架均保留操作记录。

## 13. 客服接待工作台

### 13.1 范围

客服工作台供企业客服人员使用，不替代链辽AI。客服继续通过企业微信扫码身份登录，后端根据企业归属、客服角色和有效席位授权。

本阶段只交付桌面接待工作台、后端接口和可测试协议，不修改 H5 客户入口。因此正式用户消息接入属于后续集成，不作为本阶段线上闭环声明。

### 13.2 三栏布局

左栏是待接入、接待中和已结束会话，显示未读数量、最后消息、等待时间、客户/企业和来源。

中栏是当前会话，支持文本、图片、文件、系统事件、消息失败重试、快捷回复和游标加载历史消息。

右栏展示客户与企业资料、咨询来源、最近浏览、标签、备注和历史咨询，并提供查看企业、查看相关产品、加入商机跟进、转接和结束会话。

### 13.3 会话状态

```text
WAITING（等待接入） → SERVING（接待中） → CLOSED（已结束）
                         ↓
                    TRANSFERRING（转接中） → SERVING
```

- 新会话进入企业待接入池；
- 客服手动接入时由服务端版本控制防止重复抢单；
- 只有当前负责客服可以发送消息和结束会话；
- 只能转接给同企业、在线且有客服席位的用户；
- 已结束会话保持只读，新咨询创建新会话。

### 13.4 角色

- 普通客服：接入、回复、转接和结束自己的会话；
- 客服主管：查看企业全部会话、重新分配和查看客服工作量。

权限必须由服务端校验，前端隐藏按钮只用于体验优化。

### 13.5 实时与补偿

V1 使用 HTTP 写入和游标增量轮询：

- 活跃窗口每 2–3 秒获取新增会话和消息；
- 只传输最后游标之后的数据；
- 应用最小化后降低轮询频率；
- 网络恢复后从最后成功游标补齐；
- 客户端消息 ID 用于发送重试幂等；
- 状态层与传输层分离，后续升级 WebSocket 时不重写页面状态管理。

## 14. 消息中心

消息中心聚合：

- 客服新会话和未读消息；
- 新供需匹配；
- 商机跟进提醒；
- 发布审核结果；
- 会员、积分和订单变化；
- 项目解锁结果；
- 版本更新和系统异常。

支持已读、全部已读、按类型筛选和跳转业务对象。业务通知来自 `cloud-service`，版本和运行时通知来自 Electron 主进程。当前正在查看的客服会话不重复弹出系统通知。

## 15. 桌面工具中心

工具中心复用现有壳能力，集中展示：

- 客户端版本；
- AionCore 运行状态、版本和解析来源；
- 企业 API 地址和连通状态；
- 当前企业会话；
- 系统通知权限；
- 更新通道和最后检查时间；
- 本地缓存与日志目录。

支持重新检测 AionCore、测试企业接口、检查更新、打开日志目录、复制脱敏诊断信息和清理非关键缓存。正式版不显示开发工具入口，开发版继续允许 F12。

## 16. 桌面技术边界

### 16.1 shared contracts

企业命令、请求/响应 schema、ID 校验、业务枚举和错误码放在跨进程公共层。renderer、preload 和主进程使用同一份类型定义。

### 16.2 renderer

renderer 只负责展示、交互和页面状态，不读取文件、不访问 Node.js API、不直接拼接任意后端 URL，也不注入可信身份字段。

### 16.3 preload 和 IPC

preload 只暴露固定白名单命令。所有结果使用可校验的统一 envelope；新增供需、会员、客服和消息命令必须进入 schema 和固定 IPC 通道。

### 16.4 主进程

主进程负责：

- 读取当前企业会话并注入 `openid` 和桌面会话凭据；
- 开发模式使用 `http://127.0.0.1:12580/`，生产模式只读取受控的打包环境配置；
- 固定 API 路由和超时；
- 校验后端响应；
- 脱敏日志；
- 原生通知、托盘、运行诊断和版本更新；
- 阻止 renderer 覆盖身份字段或调用任意 URL。

### 16.5 `cloud-service`

后端为桌面端提供稳定、统一的 lower camel case 契约，并负责：

- 桌面会话、企业归属和角色授权；
- 幂等、事务、唯一约束和并发控制；
- 旧数据类型与新业务枚举映射；
- 会员权益、积分、支付回调和发布审核；
- 客服会话、消息、分配、转接和审计；
- 业务聚合指标和消息通知。

桌面端不直接依赖多个旧 Controller 的不一致返回格式。

## 17. 身份、安全和数据规则

- 明文 `openid` 继续作为业务查询标识，但不能单独证明调用者身份；
- 登录成功后签发可验证、可过期、可撤销并绑定 `openid` 的桌面会话凭据；
- 收藏、跟进、解锁、发布、积分、订单、客服和消息写操作同时校验凭据与 `openid` 绑定关系；
- `userId` 接受任意非零有符号整数；所有其他业务 ID 也接受正数或负数，不能使用“必须大于零”的通用校验；
- 客服数据严格按企业隔离；
- 支付、积分扣减、权益消费、收藏和消息发送均需要幂等键；
- 日志禁止记录完整 `openid`、手机号、支付凭据、会话凭据和客服消息正文；
- renderer 不能通过对象展开或隐藏字段覆盖主进程注入的身份。

## 18. 错误模型

企业接口统一区分：

- 会话失效；
- 无业务权限；
- 会员权益不足；
- 参数错误；
- 数据不存在或已下线；
- 幂等重复；
- 网络不可用或请求超时；
- 服务端异常；
- AionCore 不可用；
- 客户端版本过低。

页面根据错误类型提供重新登录、重试、查看权益、刷新状态或打开诊断工具等操作，不再只显示“企业服务返回异常状态”。

## 19. 开发阶段

### 阶段 0：公共基础

- 企业字体、视觉变量、卡片壳和滚动结构；
- 写操作桌面会话与服务端授权边界；
- 公共错误模型、ID 规则和契约。

### 阶段 1：收藏与项目商机

- 统一收藏、我的收藏；
- 商机跟进页面和状态流转；
- 项目匹配、权益校验和解锁交互。

### 阶段 2：供需对接

- 供需大厅、详情、推荐、发布和对接记录；
- 可解释匹配与商机联动。

### 阶段 3：会员与企业运营

- 会员账户、积分账本、套餐权益和二维码支付；
- 企业、产品和供需发布审核。

### 阶段 4：客服工作台

- 客服协议、会话、消息、分配和转接；
- 三栏接待 UI、快捷回复、客户资料和业务联动；
- 测试会话与契约验收，不声明 H5 已接入。

### 阶段 5：消息与桌面工具

- 聚合消息中心；
- 运行诊断和现有更新能力整合；
- 完整安装、真实身份、权限矩阵和 Windows 验收。

每个阶段保持可独立提交、验证和回滚，不把所有模块堆到一个不可审查的提交中。

## 20. 验收标准

### 20.1 视觉与布局

- 企业工作台使用微软雅黑和企业公共视觉变量；
- 企业卡片、菜单、按钮和表单遵循统一圆角、阴影和间距；
- 链辽AI视觉不受影响；
- 左侧菜单、主内容、客服会话列表和消息区可正确独立滚动；
- 页面内容不会继续把 Electron 窗口整体拉长。

### 20.2 业务

- 收藏刷新后状态一致，重复操作不产生重复有效记录；
- 项目可以稳定执行收藏、跟进、权益检查和幂等解锁；
- 供需发布、筛选、匹配、询价和对接记录形成闭环；
- 会员、积分、订单、权益和发布额度均以服务端为准；
- 客服可以完成接入、回复、转接和结束测试会话；
- 消息可以标记已读并跳转到正确业务对象；
- 页面不显示虚构业务数字或静默 Mock 数据。

### 20.3 工程质量

- 新增用户文案进入 i18n；
- 新接口具有 schema 和服务端契约测试；
- 新运行逻辑具有聚焦单元测试；
- 核心页面具有 loading、empty、error、permission denied 和 success 状态测试；
- 关键跨页流程具有 renderer 集成测试；
- 客服和扫码登录具有 Electron E2E 或等价端到端验证；
- TypeScript、lint、format、i18n 校验和相关测试通过；
- 开发版 F12、本地 API、AionCore 和现有更新能力保持可用。

## 21. 明确不在本阶段内

- 修改 `vip_store` 增加真人客服入口；
- 给链辽AI或普通设置页做同样的明亮主题改造；
- 在 renderer 中直接调用微信支付或把订单标记为成功；
- 在没有真实数据和接口时制作业务假指标；
- 用 WebSocket 重构现有网关；
- 把企业 AI 上下文写操作扩展混入本次各业务阶段；该能力继续遵循原企业 AI 设计和单独计划。

## 22. 主要风险与控制

| 风险                              | 控制方式                                                 |
| --------------------------------- | -------------------------------------------------------- |
| 旧后端模块多、返回格式不一致      | 建立桌面聚合契约和固定路由，不让 renderer 适配多个旧格式 |
| `openid` 可明文传递导致写操作冒用 | 额外校验与 `openid` 绑定的可撤销桌面会话凭据             |
| 收藏和权益重复扣减                | 唯一约束、幂等键、事务和服务端最终状态返回               |
| 会员/支付复用错误业务表           | 实施前审计现有表和回调，仅复用语义一致的能力             |
| 客服没有 H5 客户入口              | 明确本阶段只验收桌面、后端和测试协议，不宣称线上闭环     |
| 大范围功能导致无法审查            | 按阶段拆分提交，每阶段完成测试后再进入下一阶段           |
| 企业明亮主题污染链辽AI            | 企业根节点作用域变量，不修改全局主题语义                 |
