# 企业业务实体负数 ID 兼容设计

## 背景

企业桌面端通过微信扫码取得 `openid`，后端据此查询用户、企业关联、企业和角色。现场账号已经存在完整关联，但其历史用户主键为 `-60`。项目中的企业、产品、项目、角色、收藏记录等其他业务实体同样可能使用负数历史主键。当前后端与 Electron 多处把实体 ID 限制为正整数字符串，既会让账号被误判为未注册，也会拒绝后续合法业务数据。

## 目标

所有企业业务实体 ID 统一接受非零有符号十进制整数字符串。该规则覆盖用户、企业、角色、产品、项目、收藏记录以及企业模块请求和响应中的其他实体主键。分页、数量、金额、状态码、等级和时间等非 ID 数值不在本次调整范围内。

明确契约如下：

- 所有业务实体 ID：匹配 `^-?[1-9][0-9]*$`；例如 `60`、`-60` 有效。
- 所有业务实体 ID：`0`、`-0`、`+60`、小数、空白和非数字无效。
- `pageNum`、`pageSize`、数量、状态码等非 ID 数值继续使用现有正数或非负数规则。
- 不修改数据库主键，不迁移历史关联，不改变 `openid` 查询方式。

## 方案比较

### 方案 A：全链路统一实体 ID 契约（采用）

后端用户上下文、扫码轮询响应、Electron API 客户端、IPC 桥、请求模式和响应规范化逻辑使用同一条实体 ID 契约。优点是与真实数据库兼容，而且登录与后续业务数据的信任边界保持一致；缺点是需要系统检查两个仓库内所有企业实体 ID 校验点。

### 方案 B：只修改后端

后端能够返回合法负数 ID，但 Electron 主进程或通用响应规范化仍会拒绝它们，登录或后续业务请求最终仍失败。因此不采用。

### 方案 C：迁移数据库负数主键

需要同步更新用户、企业关联、角色及其他潜在外键，影响面和数据风险远高于兼容读取。因此不采用。

## 组件改动

### cloud-service

1. `DesktopEnterpriseServiceImpl`
   - 为 `userId`、`companyId` 与 `roleId` 使用统一的非零有符号整数规范化逻辑。
   - 返回的 ID 仍统一为规范化十进制字符串。

2. `CommonQrCodeServiceImpl`
   - 注册身份判定允许非零有符号 `userId` 与 `companyId`。
   - 可选 `roleId` 同样允许非零有符号整数。
   - 白名单响应结构保持不变。

### AionUi

1. `EnterpriseApiClient`
   - 解析 `AUTHENTICATED` 轮询结果时允许非零有符号 `userId` 与 `companyId`。

2. `enterpriseBridge`
   - 保存会话前使用统一实体 ID 校验，允许非零有符号 `userId` 与 `companyId`。

3. 企业公共请求和响应规范
   - 企业、产品、项目、角色、收藏记录等实体 ID 使用统一的非零有符号整数校验。
   - 分页、数量、状态、等级、金额与时间字段维持现有校验。

公共 `EnterpriseUserContext` 类型仍使用字符串，不需要修改 IPC 消息结构或渲染层。

## 数据流

1. 微信回调把本次扫码的 `openid` 写入 Redis。
2. 桌面轮询接口读取 `openid` 并查询企业用户上下文。
3. 后端把历史主键 `-60` 规范化为字符串 `"-60"`，确认用户与企业实体 ID 都有效后返回 `AUTHENTICATED`。
4. Electron API 客户端验证返回结构，IPC 桥再次验证并保存 openid 会话。
5. 渲染层进入企业工作台；后续请求继续把 `userId` 作为字符串传给现有接口。

## 错误处理与安全边界

- 任一业务实体 ID 为 `0` 或格式异常时继续按无效数据处理。
- 负数仅表示合法历史主键，不改变权限、会话或对象归属校验。
- 不放宽 openid、登录会话、二维码、IPC 发送方或响应白名单校验。
- 不把 openid 或数据库凭据写入日志和测试快照。

## 测试策略

按测试驱动依次覆盖：

1. 后端用户上下文：`userId=-60`、`companyId=-2001`、`roleId=-7` 时返回 `registered:true`。
2. 后端扫码轮询：相同上下文返回 `AUTHENTICATED`，并保持响应白名单。
3. 后端边界：任一必需实体 ID 为 `0` 或格式异常时仍不通过。
4. Electron 登录链路：API 客户端和 IPC 桥接受负数用户与企业 ID，继续拒绝零和异常格式。
5. Electron 业务数据：企业、产品、项目及其他实体请求/响应接受负数 ID；分页、数量和状态规则不变。
6. 运行 cloud-service 定向 Maven 测试、AionUi 企业定向 Vitest 测试和 AionUi 打包检查。

## 非目标

- 不修改企业注册 H5。
- 不新增接口或数据库字段。
- 不改变数据库历史数据。
- 不把实体 ID 规则扩展到分页、数量、金额、状态码、等级或时间字段。
