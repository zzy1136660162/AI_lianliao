# 企业码高密度档案列表设计

## 目标

将 Electron 企业码列表从传统数据表格调整为高密度横向企业档案列表，使用户无需进入详情即可浏览企业主体信息、会员状态和最多三项重点产品。

## 已确认方案

- 每家企业占用一条约 150–165px 高的横向档案行。
- 左侧展示企业 Logo；中部展示企业名称、会员标识、行业、法定代表人、注册资本、成立时间、企业类型、地区、地址与主营摘要。
- 右侧展示最多三项重点产品，产品图片和名称均可进入产品详情。
- 整行支持选中和双击进入企业详情，保留键盘操作；“查看详情”作为明确操作入口。
- 列表采用统一白色表面与轻量行分隔，不给每条记录叠加厚重卡片阴影。
- 重点产品失败或为空时不阻断企业主体列表。

## 数据方案

Electron 的 `company.list` 改用新的桌面聚合接口。接口先分页查询企业，再根据当前页企业 ID 一次性查询每家企业最多三项公开产品，并将产品数组与产品总数合并到企业记录中。

企业列表需要保留现有 Oracle 查询已经返回但 Electron 当前未映射的字段：

- `TEMP_PIC` → `logoUrl`
- `RES_COST` → `registeredCapital`
- `CORPORATION` → `legalRepresentative`
- `FOUND_TIME` → `establishedAt`
- `COM_TYPE` → `companyType`

H5 继续使用原有 `getQiYeMaCompanyList`，不改变现有响应和调用方式。

## 响应与降级

- 产品批量查询只接收当前分页企业 ID，最多返回每家企业三条产品和总数。
- 无产品时返回空数组和 `0`，不额外发起逐企业请求。
- 图片只通过 Electron 现有可信域名校验后显示；失败时使用文字占位。
- 聚合接口异常时沿用企业列表现有错误状态，不返回半结构化脏数据。
