## 5. 正确性与安全边界

助手不会直接把大语言模型生成的企业名、产品名或项目名称展示给用户。

实际链路为：

```text
用户问题
  -> 模型生成结构化检索计划
  -> 资源适配器调用真实业务接口并翻页
  -> 模型只对真实候选 ID 排序
  -> 丢弃未知 ID
  -> 重新关联可信业务对象
  -> 展示企业、产品或项目卡片
```

这能保证：

- 模型可以理解自然语言，但不能伪造数据库结果。
- 模型排序失败时仍能返回真实候选。
- 联系人、电话等受限信息不会进入排序模型。
- “其中、这里面、上一批”等追问只引用当前会话中的有限可信摘要。

## 7. 最终判定

当前版本的架构、编排、类型约束、降级逻辑和页面展示已经通过关键测试。

当前阻塞项不是资源适配器代码测试失败，而是本地微服务运行状态不一致：

- Nacos 中没有 `cloud-api` 实例；
- 网关无法转发模型规划请求；
- 12585 的独立实例没有完成有效模型调用。

只有在恢复服务注册并让第 4 节四个真实输入通过后，才能给出“AI 已确认能稳定识别用户问题并正确显示真实列表”的最终结论。
